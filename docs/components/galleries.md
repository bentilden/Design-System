# Galleries

Galleries are a first-class content component for photography, design, and image-heavy story entries.

## Anatomy

| Part | Source | Notes |
| --- | --- | --- |
| Gallery entry field | `gallery` Matrix field | Allows one Gallery block. |
| Images field | `images` Assets field | Allows multiple images. |
| Gallery style | `galleryStyle` dropdown | Controls inline vs grid treatment. |
| Wrapper | `bt-control-gallery2` | Generated by `_matrix/default`. |
| Image wrapper | `bt-control-image` | Carries `data-src` for lightGallery. |
| Image file | `bt-image-file` | Applied to grid thumbnails. |

## Layout

The matrix block defaults to a two-column grid that becomes three columns at large viewports:

```twig
{% set gridCols = "grid-cols-2 lg:grid-cols-3" %}
```

Inline galleries and single-image galleries remove the grid column class:

```twig
{% if galleryStyle == "inline" or images|length == 1 %}
  {% set gridCols = "" %}
{% endif %}
```

## Behavior

- Images lazy-load with `lazysizes`.
- Images open through lightGallery zoom behavior.
- Multi-image galleries use optimized thumbnails and `sizes="20vw"`.
- Inline or single-image galleries use larger optimized images and `sizes="90vw"`.

## Accessibility

Grid images use `alt="{{ image.title }}"`. That is better than an empty attribute, but content guidance should decide whether image title is enough or whether an explicit alt field is needed.

Lightbox behavior still needs keyboard and screen-reader review.

## Open Decisions

- Decide whether `gallery.twig` and `gallery2.twig` are both supported or whether `gallery.twig` is deprecated.
- Decide whether captions should be associated with images programmatically, not just visually.
- Decide whether gallery style names should be documented for authors.
